# 逐页 · 小说 TXT 下载器

Windows 本地软件。批量加入小说目录链接，选择保存文件夹，将章节按目录顺序合并为 UTF-8 TXT。

从私人GitHub仓库取回源码、在另一台Windows电脑配置和继续修改，见 [GITHUB_SYNC.md](GITHUB_SYNC.md)。仓库不包含EXE、运行环境、小说正文、下载断点或浏览器登录资料；首次需按说明配置Python与内置浏览器组件。

## 启动

双击项目目录中的 `启动下载器.cmd`，优先启动新版 v11-fix9，沿用项目的配置和缓存。发布版不需要另装 Python；移动软件时需要整份发布文件夹，不能只复制 exe。当前正在运行的旧版不会自动替换；先“停止并保存”并退出旧版，再打开新版，避免两个版本同时使用缓存和浏览器资料。

## 使用

1. 每行粘贴一本书的目录链接，点击“加入队列”；也可导入 UTF-8 链接文本。
2. 选择保存文件夹。没有指定时，默认保存到软件所在文件夹下的“下载”。
3. 建议先“试下前 3 章”检查站点适配，再开始全量下载。试下载文件明确标记为“试下载”，不算全量验收。
4. “开始 / 继续下载”处理选中任务；未选中时处理尚未完成的整个队列。
5. “暂停全部”会在当前请求结束后暂停整批；“停止并保存”保留全部任务缓存。“暂停/继续选中”和“停止选中”只作用于选中的任务（可多选，包括排队中的任务），其他任务继续。再次开始会校验并复用缓存。
6. “刷新目录 / 追更”重新读取目录，已有正确章节不重复下载。默认续传使用原目录快照，日志显示快照时间。
7. “移除选中”仅移出任务列表。“删除文件和缓存”支持多选：先显示范围，确认后删除当前保存目录下来源链接匹配的 TXT、报告（含子目录中的阶段样本）和整本缓存，并移除任务。正在下载的任务不能删除；删除后无法断点续传。不会按书名模糊匹配，也不会清理浏览器登录配置。被手工移动到保存目录外、失去配套报告的导出文件无法可靠识别，不会自动删除。

可以输入分类页或书单页，然后选择“解析列表并选书”。目前识别 `/book/数字/` 和 `/novel/书名` 形式的链接，只读取给定列表页，不自动遍历整站。

## 网络与浏览器

- v11-fix8：41nr后台请求若收到短小的普通nginx 403、同时有 `CF-Cache-Status: HIT` 和正数 `max-age`，对该页自动冷却重读最多2次（60秒、120秒），显示“访问冷却”和倒计时，同站暂停新请求，其他站点继续。遵守更长的 `Retry-After`；超过5分钟自动恢复窗口则停止并保存。成功后本轮保持单请求并发。没有这些缓存证据的403、401、权限或登录页不启用此恢复；两次后仍拒绝也会明确结束本轮并保留断点，不无限等待。界面“刷新”正常重新加载，但只查看失败页不会启动下载。
- 同时下载书数可设 1～8，默认 3，表示不同站点同时运行的书数；同一主站固定每次处理 1 本，其他书排队。每书章节并发可设 1～4，默认 3；每站并发上限可设 1～4，默认 2，约束实际网页请求。章节可以同时下载，章内分页仍顺序读取，TXT 最终按目录顺序合并。
- 自动调节开启时站点请求并发从 1 开始，连续 32 次稳定成功且页面响应耗时超过请求间隔时，才增加一个槽位，直到设定上限。短页面不会因为成功次数多而无收益加并发。响应明显变慢、失败或验证会降低并发；出现验证或 429 后，本轮保持单请求并发。关闭自动调节时使用设定上限，受限后仍降到 1。
- “网页请求间隔”是同站新请求开始之间的最小间隔，所有书共用，不能靠增加书数绕过；没有额外的章间等待，页面结束也不会重新加一遍等待。新请求真正进入 HTTP/浏览器导航时才开始计时，浏览器启动不会积攒突发请求。间隔可设 1～300 秒，原有设置保留。
- 保留“稳妥 / 均衡 / 较快”三档速度：8 秒 / 每 15 个网页请求休息 60 秒；3 秒 / 每 30 个请求休息 15 秒；1 秒 / 每 50 个请求休息 10 秒。新版 GUI 按站点合并限速计数，不额外增加随机浮动。并发上限不会改变这一最低间隔；短页面或较长间隔时同站实际并发可能达不到上限。CPU/网络/网站负载不同，提速幅度需实测。
- 默认使用内置 WebView2 浏览器。点击“站点浏览器”在软件内部查看网页、完成手动验证；“返回下载队列”保留会话，后台继续下载。批次结束不关闭内置会话；退出软件时保存并关闭。可在浏览器模块顶部选择“独立浏览器”，下轮任务改用原专用 Edge/Chrome。自动选择模式下，41nr 和已有对应登录资料的站点使用所选浏览器，其他网站先使用 HTTP。
- 任务因明确 HTTP 错误暂停后，选中该任务点“查看失败页”，直接在内置浏览器检查出错地址。检查使用独立页面，不启动整本下载，不改动后台下载页面；任务恢复正常后再返回队列点“开始 / 继续下载”。出错地址随队列及断点保存，重启后仍可查看。浏览器底部标题和 HTTP 错误码只对应实际显示页，后台章节和其他站点不会覆盖它；目录页停留在前台不表示后台还在解析目录。普通 403 没有可操作验证时仍暂停本站，不自动反复刷新。
- 浏览器建立正常会话后，同源目录分页和已适配站点正文优先通过浏览器后台 HTTP 获取 HTML，复用 Cookie 和连接，不逐章加载图片、样式表和页面脚本。动态正文、跳转或验证会回退到专用浏览器。未知站点首次正文会对照原始 HTML 和渲染后的排版，不一致则继续渲染。每个 HTTP 章节线程复用自己的 Client，不按章节重建连接池。
- v11-fix7：待下载页面使用 `fetch cache: reload` 获取当前响应并更新浏览器 HTTP 缓存，避免复用源站设置长缓存期限的旧 403。软件自己校验过的章节/分页断点仍优先读取，成功章节不会因此重新下载。内置浏览器“刷新”使用忽略 HTTP 缓存的真实重新加载，保留 Cookie 与登录资料；不清空缓存目录或账号。若当前新响应仍为403，仍正常暂停本站并保留断点。
- 内置浏览器使用 `data/webview2-profiles/站点` 独立资料，不读取日常浏览器账号。已经手动验证原型的两站继续使用 `evidence/webview2-prototype/profiles` 对应资料目录，不能删除这份目录，否则需重新登录。原专用 Edge/Chrome 资料不作格式转换，选择独立浏览器仍沿用它。同站任务共享 Cookie，网站会话过期或确实再次要求验证时仍需正常处理；不能承诺永久免验证。
- 网站要求登录或真人验证时，同站新请求暂停，由一个任务的标签页提示处理；其他已运行站点继续。选中等待任务再点“打开验证页面”；未选中等待任务时打开第一个等待任务。恢复可读后自动继续；重复点击“已处理”不会放行仍受限页面。同站另一个受限标签页会等待并复用更新后的会话；网站确实再次要求验证时仍需正常处理。
- 内置模式需要 Microsoft Edge WebView2 Runtime（本机已核实安装）；独立模式需要 Edge 或 Chrome。若运行时缺失，界面会说明启动失败，可选择独立模式。HTTP 默认直连，可勾选使用环境代理；浏览器使用其系统网络设置。
- 普通 HTTP 收到 401、403、429 或发现验证页后，该站本轮停止，保留缓存。浏览器及其后台 HTTP 收到普通 401/403 且没有明确验证或登录内容时，显示“访问被拒绝”并结束本站本轮任务，不等待真人点击。浏览器及其后台 HTTP 收到普通 429 时，暂停同站新请求，按服务器 `Retry-After` 冷却；没有有效提示时从 30 秒开始指数退避。最多重试 3 次，成功后本轮仍单并发、间隔至少 3 秒；连续失败结束该站本轮任务并保留断点。只有明确验证挑战或确实要求登录的页面，才保留会话等待正常手动处理。其他站点继续。没有指纹伪装、代理池轮换、自动验证码或付费内容解锁。
- v11-fix1 将普通 404/410 和明确的“404 Not Found”错误页记为该章缺页，不进入人工验证、不重复打开错误页，也不因此降低同站并发；其他章节继续。报告记录具体缺失分页 URL 和 HTTP 状态，缺页小说标记为“待核对”。再次继续时保留已下载分页，只重试缺失部分。当前停止判断以v11-fix9的目录相邻三章同类错误规则为准。没有明确验证要求的空白正文或其他 HTTP 错误也不会冒充真人验证。
- v11-fix2 在续传校验结束后汇总全部缓存章节，避免快速校验时界面只显示第一章；本轮失败原因保持显示，不再被“本轮处理结束”盖住。对实际核查过的 41nr 正常中文正文，只允许原样保留少量段首 U+E4C6，并在报告中列为待核对；不猜测它的字体含义，不替换为空格。其他未知私用字符、替换字符或正文编码问题仍拒绝导出。
- “每书章节并发 3”表示最多三个章节任务交错推进，并不覆盖站点请求上限或请求间隔。每站上限设为 1 时最多一个网页请求在途；请求只需约半秒而间隔设为 5 秒时，即使上限设为 3，也通常没有三个请求同时在途。新一轮设置生效前不会改正在运行的任务。
- 网络错误最多重试 2 次，采用退避等待；停止按钮在退避期间也有效。单次页面超时为 20～25 秒。

## 排版与完整性

- v11-fix9：相同解析错误是否连续，以原目录中相邻章节判断，不以重试缺口的完成顺序判断。第613、630、915章这类相隔很远的旧失败，不再合并触发整本停止；真正目录相邻三章出现相同非缺页错误时仍暂停，异步章节乱序完成也能识别。可疑正文仍不缓存、不冒充完整章节，缺章报告保留。已下载章节和排版不变。
- 保留章节标题、自然段、明确空行、全角/不换行空格及文本缩进；不改写、翻译或繁简转换。
- 网页字体、颜色、字号、图片和 CSS 精确行距不能由 TXT 表达。普通 HTML 源码的缩进换行按照浏览器语义处理；`pre` 内空白原样保留。
- 搬山人适配去掉段落评论计数，并依据其公开样式表将两字首行缩进转换为两个全角空格。图片正文、未解码文字、限制阅读面板不会冒充完整正文。
- 通用未知站点可能需新增专用选择器或浏览器模式；不承诺所有网站直接可用。
- 同名章节按 URL 分别下载和保留，提示核对，不按标题静默删章。目录原顺序保留。
- 每章检查分页循环、缺页、标题一致性、异常字符和重复正文。缺章、重复标题、章号跳跃会写入报告。
- `已发布章节` 文件表示下载时所见目录全部通过检查，不表示作品已完结，也不能证明源站本身没有删节。
- `待核对` 文件可能不完整；缺章与疑点列在同名 `.report.json` 中。

## 文件命名

- TXT 使用 `书名（作者）.txt`，没有作者就用 `书名.txt`；不再附加网站宣传词、时间戳、状态或 URL 摘要。41nr 的旧目录快照会在续传时清理书名并提取网页标题中已有的作者，不重新请求目录。已导出的旧文件不批量改动。
- 完整文件保存在选择的目录；试下载、缺章或待核对的文件分别进入“试下载”“待核对”子目录，文件名仍保持简洁。
- 同一来源重复导出或追更时，只有报告来源和文件校验值都匹配，才更新原路径。不同来源的同名书、没有可信报告的文件、被手工修改的 TXT 会另存到“同名书/来源ID”子目录，保留原文件；文件名不追加标记。报告随 TXT 同名保存。

## 数据与日志

- 正文：选定目录下的 TXT；同一来源的已校验导出可更新，其他来源或手工修改的文件保留。
- 检查报告：与 TXT 同目录，同名 `.report.json`。
- 续传缓存：选定目录下 `.novel-cache/书籍ID/`，含目录快照、章节、原页面和 `manifest.json`。
- 队列及偏好：软件目录 `data/`。
- 日志：软件目录 `logs/session-*.jsonl`，主界面同步显示进度；点击“查看日志”打开可滚动的详细日志窗口，关闭该窗口不影响下载。网页正文不会写入运行日志。
- 每个正文分页保存后会显示分页进度；整章完整后，章节完成数才加 1。日志记录本轮设置、后台 HTTP/浏览器回退与限流冷却，运行中修改配置于下轮生效。
- 目录阶段显示“目录第 N 页 / 发现 N 章”，不是已下载章节数；读完目录后开始正文下载。有书需处理时，运行其他书也会保留数量提示，选中失败任务可查看原因。
- 404/410 缺页记入缺章报告并继续后续章节；三个不同的章节问题不会合并停止整本。原目录中相邻三章出现相同的其他错误才暂停本书，旧缺口与并发完成顺序不会被误算成连续；网站验证、登录及访问限制仍按原规则处理。缺失或无法确认的正文不会冒充完整小说。
- 退出软件会通知工作线程保存并退出；请求尚未结束时可能需等待最多约 25 秒。软件没有本地服务器或监听端口。

Python 3.12。安装 `requirements.txt` 到项目独立虚拟环境，运行 `launcher.py` 启动开发版；`build.ps1` 生成 Windows 发布文件夹。

离线测试：`.venv\Scripts\python.exe -m pytest tests -q`

命令行下载：`.venv\Scripts\python.exe launcher.py --cli URL --output downloads --delay 5`

命令行支持 `--limit 3`、`--inspect`、`--refresh`、`--stop-file logs/stop-job`；创建指定停止文件即可在当前请求结束后保存退出。删掉或换用停止文件后才可重新启动。`--browser-minimized --profile data/browser-profile` 保持正常浏览器并最小化，验证时从任务栏打开专用窗口；`--browser-headless --profile 路径` 使用无窗口模式，遇限制退出并保留缓存。
